### 🔴 批阅意见

> [!CAUTION]
> **严重程度：❌ 代码存在多处严重逻辑错误，无法正确运行**

#### 1. 🚨 致命问题：`goto` 跳转到未初始化的变量

```c
if(a[y-1][x]==0){
    goto fangshibing;  // 跳到这里...
}
int x_cun=x;           // 但这两行被跳过了！
int y_cun=y;
// ...
fangshibing:;
x=x_cun;               // x_cun 是未初始化的垃圾值！
y=y_cun;               // y_cun 也是垃圾值！
```

**后果**：`x_cun` 和 `y_cun` 未初始化就被使用，导致**未定义行为**。

---

#### 2. 🚨 致命问题：缺少回溯机制

回溯算法的核心是**"尝试 → 递归 → 撤销"**，你的代码：
- ✅ 放置了卫兵：`a[y][x]=1;`
- ❌ **从未撤销**！

```c
// 标准回溯应该是这样：
a[y][x] = 1;           // 放置
count++;
pailie();              // 递归
a[y][x] = 0;           // 撤销 ← 你缺了这个！
count--;
```

**后果**：递归回来后，卫兵还在原位置，导致后续分支状态错乱。

---

#### 3. 🚨 致命问题：覆盖逻辑完全错误

你的代码把"被覆盖的格子"和"放卫兵的格子"混为一谈了：

```c
a[y][x-1]=1;   // ❌ 这是在"放卫兵"！不是标记"被覆盖"
a[y+1][x]=1;
```

**正确做法**：需要两套信息：
- `guards[i][j]`：记录 `(i,j)` 是否有卫兵
- `covered[i][j]`：记录 `(i,j)` 被覆盖了几次（可以是计数器）

或者只用一个 `covered` 数组，放卫兵时给周围 5 个格子 `+1`，回溯时 `-1`。

---

#### 4. ⚠️ 边界访问越界

```c
}else if(y==0){
    a[y][x-1]=1;   // 当 x=0 时，x-1=-1，越界！
    a[y+1][x]=1;
    a[y][x+1]=1;
}
```

你没有检查 `x > 0` 就访问了 `a[y][x-1]`。

---

#### 5. ⚠️ 结束条件检查不完整

```c
if(y==m-1 && x==n-1){
    // 只检查了是否走到最后一格
    // 没有检查所有格子是否都被覆盖！
}
```

应该遍历整个网格，确认每个格子都被覆盖。

---

#### 6. 💡 代码风格建议

| 问题 | 建议 |
|------|------|
| 使用 `goto` | 尽量避免，用 `if-else` 代替 |
| 全局变量太多 | 封装到结构体或传参 |
| 变量名 `a`, `x`, `y` | 用 `grid`, `col`, `row` 更清晰 |
| 没有注释 | 关键逻辑加注释 |

---

### ✨ 修改方向

1. **分离覆盖计数**：用 `covered[i][j]` 记录格子被覆盖次数，放卫兵时 `+1`，回溯时 `-1`
2. **补充回溯**：递归返回后，撤销放置的卫兵
3. **消除 `goto`**：用正常的 `if-else` 分支
4. **边界检查**：访问相邻格子前检查下标合法性
5. **结束检查**：遍历所有格子确认覆盖
