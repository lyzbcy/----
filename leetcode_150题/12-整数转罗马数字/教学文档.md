# 12. 整数转罗马数字 — 教学文档

---

## 一、问题分析

给定整数 `num`（范围 `[1, 3999]`），要求输出对应的罗马数字字符串。

罗马数字有 7 个基本符号，另有 **6 个特殊减法组合**（IV、IX、XL、XC、CD、CM）用来避免连续出现 4 个相同符号。总共 **13 个"原子片段"**，每个片段都有固定的整数值。

---

## 二、思路解析

### ❌ 错误直觉：按位处理（千、百、十、个）

很多人会想把数字拆成千位、百位、十位、个位，然后分别查表。这种方法**非常繁琐**，需要四张独立的映射表，代码冗长且容易漏情况。

### ✅ 正确思路：贪心 + 统一对照表

关键观察：将 13 个"原子片段"**从大到小排列成一张表**，然后贪心地从最大值开始匹配：

- 每次找到第一个 `≤ num` 的值，拼接对应符号，并从 `num` 中减去该值
- 重复直到 `num == 0`

13 个原子片段（从大到小）：

| 值   | 符号 |
|------|------|
| 1000 | M    |
| 900  | CM   |
| 500  | D    |
| 400  | CD   |
| 100  | C    |
| 90   | XC   |
| 50   | L    |
| 40   | XL   |
| 10   | X    |
| 9    | IX   |
| 5    | V    |
| 4    | IV   |
| 1    | I    |

**为什么这样是正确的？**  
因为每个"片段"在对应进制层级内永远是最优选择，贪心不会产生后悔：选了更大的符号不会影响后续更小范围的处理。

---

## 三、算法详解

```
建立 values[]  = {1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1}
建立 symbols[] = {"M","CM","D","CD","C","XC","L","XL","X","IX","V","IV","I"}

初始化 result = ""，i = 0

当 num > 0:
    当 num >= values[i]:
        result 拼接 symbols[i]
        num -= values[i]
    i++

返回 result
```

### 示例追踪：num = 1994

| 步骤 | i  | values[i] | num 当前 | 操作         | result      |
|------|----|-----------|----------|--------------|-------------|
| 1    | 0  | 1000      | 1994     | 拼接 M，-1000| "M"         |
| 2    | 1  | 900       | 994      | 拼接 CM，-900| "MCM"       |
| 3    | 4  | 100       | 94       | 跳过         | "MCM"       |
| 4    | 5  | 90        | 94       | 拼接 XC，-90 | "MCMXC"     |
| 5    | 12 | 1         | 4→跳→IV  |              |             |
| 6    | 11 | 4         | 4        | 拼接 IV，-4  | "MCMXCIV"   |

最终输出：`"MCMXCIV"` ✅

---

## 四、代码实现（C 关键片段）

```c
int values[]  = {1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1};
char *loma[]  = {"M","CM","D","CD","C","XC","L","XL","X","IX","V","IV","I"};

char *result  = malloc(20 * sizeof(char));
result[0]     = '\0';

int i = 0;
while (num > 0) {
    while (num >= values[i]) {
        strcat(result, loma[i]);
        num -= values[i];
    }
    i++;
}
```

> ⚠️ **注意**：`strcat` 是拼接字符串函数；`malloc(20)` 足够存放最长的罗马数字（"MMMCMXCIX" 约 15 字符 + `\0`）。

## 五、复杂度分析

| 指标     | 分析                                                      |
|----------|-----------------------------------------------------------|
| 时间复杂度 | **O(1)**：输入范围为 `[1,3999]`，最多拼接约 15 个符号    |
| 空间复杂度 | **O(1)**：对照表大小固定，结果字符串长度有上界            |

## 六、常见错误

| 错误类型 | 描述 | 解决方案 |
|---------|------|---------|
| 忘记 6 个特殊组合 | 只放 7 个基本符号，导致 4 输出 `IIII` 而非 `IV` | 在对照表中加入 CM、CD、XC、XL、IX、IV |
| 内存未初始化 | `result[0]` 未设为 `'\0'`，`strcat` 出错 | 申请后立即 `result[0] = '\0'` |
| 忘记 free | C 语言 malloc 后必须 free | 调用方负责释放 |
| 越界访问 | `i` 超过 12 但 `num` 还大于 0 | 不会发生（输入 ≤ 3999，表足够覆盖） |

## 七、扩展思考

1. **为什么是 13 个片段而不是 7 个？**  
   6 个特殊减法片段（IV、IX、XL、XC、CD、CM）如果不放进表里，单独处理会增加分支逻辑。统一放入表后，代码无需任何 `if` 判断。

2. **如果范围扩展到 [1, 9999999] 怎么办？**  
   古罗马数字还有上画线表示 ×1000 的写法，可以继续扩充对照表。

3. **逆问题：字符串转整数**  
   见 LeetCode 13，方向相反——从左到右扫描，遇到"小字符在大字符左边"就减法处理。
